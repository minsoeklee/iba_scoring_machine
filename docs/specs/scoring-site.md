# 동아리 회귀 프로젝트 자동 채점 사이트 — 구현 스펙

작성일: 2026-09-19
근거: [결정 지도](../wayfinder/scoring-site/MAP.md), [기술 스택 조사](../research/scoring-site-tech-stack.md)

## Problem Statement

데이터분석 동아리는 매 기수 후배 팀에게 중고차 가격 예측(회귀) 프로젝트를 내주고, 팀이 만든 모델의 예측 결과를 정답과 비교해 점수를 매긴다. 지금은 운영진이 제출 파일을 받아 손으로 채점하기 때문에 점수가 늦게 나오고, 팀은 모델을 고친 뒤 바로 결과를 볼 수 없으며, 운영진 두 사람이 졸업하면 채점 방법 자체가 사라질 위험이 있다. 또한 제공 자료에는 정답 파일이 섞여 있어(정답 `answer.csv`가 데이터 폴더 안에 있음) 그대로 배포하면 채점이 무의미해진다.

## Solution

팀이 예측 결과 CSV를 업로드하면 즉시 RMSE와 R²를 계산해 돌려주고, 리더보드에 팀별 순위를 보여주는 별도 웹사이트를 만든다. 사이트는 홈 화면, 채점 페이지, 리더보드, 미니게임 네 페이지로 구성된다. 정답은 서버 측 데이터베이스에만 두고, 팀당 하루 3회 제출 제한으로 리더보드 과적합을 억제한다. 로그인 없이 팀명과 닉네임을 자유 기입하며, 무료 티어(Vercel Hobby + Neon Free)만으로 운영해 비용 0원을 유지하고 후배 운영진이 이어받을 수 있게 한다.

## User Stories / Acceptance Criteria

### 채점 페이지

1. 후배 팀원으로서, 팀명·닉네임을 입력하고 `id,price` 형식의 CSV를 업로드하면 몇 초 안에 RMSE와 R²를 화면에서 보고 싶다. 그래야 모델을 고친 뒤 바로 효과를 확인할 수 있다.
2. 후배 팀원으로서, 제출 파일이 형식에 맞지 않으면 무엇이 잘못됐는지(헤더 불일치, 행 수 불일치, id 순서 불일치, 숫자가 아닌 값, 빈 값) 구체적인 메시지로 알고 싶다. 그래야 채점 없이 실패한 이유를 스스로 고칠 수 있다.
3. 후배 팀원으로서, 오늘 우리 팀이 몇 회 제출했고 몇 회 남았는지 제출 전에 보고 싶다.
4. 후배 팀원으로서, 하루 3회를 다 쓴 상태로 제출하면 채점되지 않고 "오늘 제출 횟수를 모두 사용했다"는 안내와 초기화 시각을 보고 싶다.
5. 후배 팀원으로서, 제출 형식 안내(헤더, 행 수 39,085, test.csv와 같은 순서, 행 순서를 바꾸지 말 것)와 `sample_submission.csv` 다운로드 링크를 채점 페이지에서 보고 싶다.

### 리더보드

6. 동아리원으로서, 팀별로 닉네임·팀명·RMSE·R²가 RMSE 오름차순으로 정렬된 리더보드를 로그인 없이 보고 싶다.
7. 동아리원으로서, 리더보드의 한 팀 행에는 그 팀의 **최고 기록(RMSE 최소)** 한 건만 표시되고, 그 기록을 낸 닉네임과 제출 시각이 함께 보이길 원한다. (Not yet specified였던 항목 — 본 스펙에서 최고 기록으로 확정. 이유: 하루 3회 제한 아래에서 팀이 실험 제출을 두려워하지 않게 하기 위함.)
8. 동아리원으로서, RMSE가 같은 팀은 R²가 높은 쪽, 그것도 같으면 먼저 제출한 쪽이 위에 오길 원한다.

### 홈 화면·미니게임

9. 처음 방문한 후배로서, 홈 화면에서 프로젝트 소개, 데이터 설명(train/test/brand_model/sample_submission), 채점 방식(RMSE 주 지표, R² 보조), 제출 규칙(하루 3회, 행 순서 유지)을 한 번에 읽고 채점 페이지·리더보드로 이동하고 싶다.
10. 동아리원으로서, 채점과 무관한 가벼운 미니게임 페이지를 열어 잠깐 놀 수 있길 원한다. 미니게임은 서버·DB와 통신하지 않는다.

### 운영

11. 운영자로서, 잘못된 제출(남의 팀명 도용, 장난 제출)을 관리자 키로 삭제해 리더보드와 해당 팀의 오늘 제출 횟수를 바로잡고 싶다.
12. 운영자로서, 정답 파일을 git 저장소에 넣지 않고도 배포·채점이 되길 원한다. 저장소가 공개되어도 정답이 새지 않아야 한다.
13. 운영자로서, 다음 기수에 데이터셋이 바뀌면 정답 테이블을 다시 적재하고 제출 기록을 비우는 절차가 문서화되어 있길 원한다.

### 제약·엣지 케이스

14. 제출 CSV의 `id` 열은 test.csv와 **행 순서까지** 같아야 한다. id 값은 고유하지 않으므로(39,085행 중 고유 31,573개) id 조인이 아니라 위치 기준으로 비교한다.
15. `price`에 음수가 있으면 거부하지 않고 0으로 클리핑한 뒤 채점하며, 결과 화면에 "음수 n건을 0으로 처리했다"고 알린다. (기존 노트북 관행과 일치.)
16. `price`가 비어 있거나 숫자가 아닌 행이 하나라도 있으면 채점하지 않고 거부한다.
17. 팀명은 앞뒤 공백 제거·연속 공백 하나로 축약·대소문자 구분 없이 같은 팀으로 본다. 리더보드에는 처음 제출된 표기를 그대로 보여준다.
18. "하루"는 한국 시간(KST) 자정에 초기화된다.
19. 업로드 파일 크기는 2 MB를 넘으면 거부한다(정상 제출은 약 0.5 MB, 플랫폼 본문 한도 4.5 MB 이내 여유).

## Implementation Decisions

### 전체 구성

- 호스팅은 Vercel Hobby, 백엔드는 Python FastAPI 단일 앱을 Vercel Functions로 실행, 데이터베이스는 Neon Postgres Free. 프론트는 프레임워크 없는 정적 HTML/CSS/JS 네 페이지. (결정 006)
- 저장소는 동아리 GitHub 조직의 공개 저장소. Vercel Hobby는 조직 비공개 저장소에서 배포할 수 없으므로 공개가 전제이며, 따라서 정답 파일은 어떤 형태로도 저장소에 커밋하지 않는다. `scoring_machine/regression/answer.csv`는 이 저장소에서 제거하거나 `.gitignore`로 막는다. (결정 002, 005, 006)
- 비밀값은 Vercel 환경변수 두 개: 데이터베이스 연결 문자열, 관리자 키.
- 채점 연산은 Python 표준 라이브러리(`csv`, `math`)만 사용한다. pandas/numpy는 콜드 스타트만 늘리고 이 규모(39,085행)에서 이점이 없다. 조사 시 벤치마크: 두 파일 파싱 + 계산이 수십 ms 수준.

### 데이터 모델 (Neon)

- `answers`: `row_no`(0부터 시작하는 위치, 기본키), `id`(test.csv의 id, 참고용), `price`(정답). 39,085행. 기수 시작 시 운영자가 스크립트로 1회 적재.
- `submissions`: `id`(자동), `team_key`(정규화된 팀명), `team_display`(처음 입력된 표기), `nickname`, `rmse`, `r2`, `negative_clipped`(0으로 처리한 건수), `submitted_at`(UTC 저장, 표시·일 계산은 KST 변환), `deleted_at`(관리자 삭제 시 기록; 삭제된 행은 리더보드·횟수 계산에서 제외).
- 제출 파일 원본은 저장하지 않는다. 점수와 메타데이터만 남긴다.

### 채점 규칙 (결정 001, 002, 003)

- 검증 순서: 파일 크기 → UTF-8 텍스트 파싱 → 헤더가 정확히 `id,price` → 데이터 행 수 39,085 → 각 행의 id가 `answers.row_no` 순서의 id와 일치 → `price`가 모두 유한한 숫자. 첫 실패 지점에서 해당 사유와 (가능하면) 문제 행 번호를 반환한다.
- 음수 price는 0으로 클리핑하고 건수를 기록한다.
- RMSE = sqrt(mean((y − ŷ)²)), R² = 1 − Σ(y − ŷ)² / Σ(y − ȳ)². 소수점은 저장 시 전체 정밀도, 표시 시 RMSE 소수 2자리·R² 소수 4자리.
- 정답은 함수 인스턴스 안에서 첫 요청 시 한 번 읽어 메모리에 캐시한다(인스턴스 재사용 시 DB 재조회 없음).

### 제출 제한 (결정 004, 007)

- 팀 식별은 `team_key`(정규화된 팀명) 문자열만으로 한다. 로그인·세션·쿠키 없음.
- 제출 처리 순서: 정규화 → 오늘(KST) `deleted_at IS NULL`인 제출 건수 조회 → 3회 이상이면 429와 초기화 시각 반환 → 파일 검증·채점 → 기록 삽입. 동시 제출 경쟁으로 4회가 기록될 가능성은 받아들인다(신뢰 집단, 실수 방지 수준이 목표).
- 남은 횟수 조회는 채점 페이지에서 팀명 입력 후 별도 요청으로 제공한다.

### API 계약

- `POST /api/submit` — multipart: `team`, `nickname`, `file`. 성공 200: `{ rmse, r2, negative_clipped, remaining_today, rank }`. 검증 실패 400: `{ error_code, message, row? }`. 한도 초과 429: `{ message, resets_at }`.
- `GET /api/leaderboard` — 팀별 최고 기록: `[{ rank, team, nickname, rmse, r2, submitted_at }]`. RMSE 오름차순, 동점 시 R² 내림차순, 그다음 `submitted_at` 오름차순.
- `GET /api/quota?team=` — `{ used_today, remaining_today, resets_at }`.
- `DELETE /api/submissions/{id}` — 헤더 `X-Admin-Key` 필수. 소프트 삭제. 키 불일치 시 401.
- `GET /api/submissions?team=` (관리자 키 필수) — 삭제할 대상을 찾기 위한 팀별 제출 목록.
- 관리자 UI는 만들지 않는다. 운영자는 `curl` 또는 브라우저 개발자 도구로 위 두 관리자 엔드포인트를 호출한다. 운영 문서에 예시 명령을 적는다.

### 페이지

- 홈: 소개·데이터 설명·채점 방식·제출 규칙·데이터 다운로드 링크(train/test/brand_model/sample_submission은 정적 파일로 제공; answer는 절대 포함하지 않음).
- 채점: 팀명·닉네임 입력, 파일 선택, 남은 횟수 표시, 제출 결과(점수·현재 순위·음수 처리 안내) 또는 오류 메시지 표시.
- 리더보드: 표 하나. 페이지 로드 시 조회, 새로고침 버튼. 캐시 없이 매번 조회(요청량이 작다).
- 미니게임: 순수 클라이언트 페이지. 어떤 게임인지는 구현 시 자유. 서버 요청 없음.
- 네 페이지 공통 상단 내비게이션.

### 기수 교체 절차 (결정 005, Not yet specified의 "관리자 기능")

- UI 없이 스크립트로 처리: (1) 새 `answer.csv`로 `answers` 재적재, (2) `submissions` 비우기(또는 기수 컬럼 없이 전체 삭제), (3) 정적 데이터 파일 교체 후 배포. 운영 문서에 명령 순서를 적는다.
- 플랫폼 계정(Vercel, Neon, GitHub 조직)은 동아리 공용 이메일로 만들고, 운영 문서에 계정 인수인계 항목을 둔다.

## Validation Decisions

- 좋은 테스트는 채점 API의 **외부 동작**만 본다: 특정 CSV를 넣으면 특정 상태 코드와 점수·오류 코드가 나오는지. 내부 파싱 함수나 DB 스키마는 직접 검사하지 않는다.
- 채점 정확성 기준값: `sample_submission.csv`를 그대로 제출하면 RMSE ≈ 13,189.79, R² ≈ −0.79가 나와야 한다(조사 중 실측). `answer.csv` 자체를 제출하면 RMSE 0, R² 1이어야 한다. 이 두 파일이 회귀 테스트의 고정 입력이다.
- 검증 실패 케이스별 테스트 입력을 만든다: 헤더 오타, 행 하나 누락, 두 행 순서 바꿈, price 빈 값, price 문자열, 음수 price(클리핑 후 성공 + 건수 확인), 2 MB 초과 파일.
- 제출 제한 테스트: 같은 팀명(표기 변형 포함 — 공백·대소문자)으로 3회 성공 후 4회째 429; 관리자 삭제 후 다시 제출 가능; KST 자정 경계는 시각을 주입할 수 있게 해 테스트.
- 리더보드 테스트: 한 팀이 여러 번 제출해도 한 행, 최고 RMSE 기준; 동점 정렬 규칙; 삭제된 제출은 제외.
- 테스트는 FastAPI의 테스트 클라이언트로 API 레벨에서 작성하고, DB는 테스트용 Neon 브랜치 또는 로컬 Postgres를 쓴다. 이 저장소에는 아직 선례가 되는 테스트가 없다.
- 프론트는 자동 테스트 없이 수동 확인: 네 페이지 이동, 채점 성공·실패·한도 초과 세 가지 화면, 리더보드 정렬, 모바일 폭에서 표가 깨지지 않는지.
- 배포 후 확인: 공개 저장소에 정답 파일이 없는지, 정적 경로로 정답에 접근되지 않는지, Vercel 함수 로그에서 첫 요청(콜드 스타트) 소요 시간 실측.

## Out of Scope

- 분류 과제(German Credit) 채점 — 폐기 결정.
- 로그인·계정·팀 코드 발급 — 자유 기입으로 확정.
- 코드/노트북 제출과 서버 실행 — 예측 CSV만 받는다.
- 관리자 웹 UI — 관리자 엔드포인트 + 문서화된 명령으로 대체.
- public/private 리더보드 분할 — 하루 3회 제한으로 과적합 억제를 대신한다.
- 점수 외 상세 피드백(오차 분포, 구간별 오차) — 첫 버전에서는 RMSE·R²·음수 처리 건수만.
- test.csv의 id 재부여 — sample_submission 형식 호환을 위해 하지 않는다.
- 후배용 모델 학습 환경 제공, 기존 3조 노트북 개선.
- 동아리 홈페이지(`pnu-iba-homepage/`)와의 통합.

## Further Notes
